# Codex 恢复阶段一

## 使用方式

用于一次执行结束、环境重启或已有结果需要继续推进时。复制下面的提示词，让 Codex 从真实仓库状态恢复，而不是重新开始全部实验。

```text
继续仓库 https://github.com/kaiwen123-yang/idea-boat-and-arm 的阶段一任务。

保持最新研究目标：效果与充分证据优先，大量随机动作和充分随机干预可以用于正式实验；最终必须实现粒子流体、波浪生成、双向流固耦合收敛验证、大规模并行和机器人学习。初期使用等效海洋载荷，腕部相机已经纳入 P1。当前任务仍是完成 P1，不自行扩展后续学习或粒子流体支线。

只使用该仓库、当前任务及仓库中已记录的用户授权核验来源，不引用个人记忆或未授权的其他项目信息，不假定上一次执行已经成功，也不把旧报告的 PASS 自动应用到当前代码。

1. 检查 Git 工作区、分支和远端。保留已有改动，读取 AGENTS.md、README.md、reports/STATUS.md、reports/phase1_status.json，以及最近一次报告、提交和运行证据。
2. 对照 configs/phase1_design.json、docs/PHASE1_SPEC.md、docs/PHASE1_ACCEPTANCE.md、docs/CAMERA_SPEC.md、docs/ARCHITECTURE.md、docs/EVIDENCE_PROTOCOL.md、docs/PHASE1_TASKS.md、docs/ROADMAP.md、docs/FINAL_FLUID_TRACK.md，整理当前真实状态。scripts/check_design.py 的解析检查不是物理或相机验收。
3. 先核对 Piper／Piper H 资产来源、版本或 SHA、许可、质量惯量和关节／夹爪限位的审计是否完成。旧 12 kg 臂质量、0.75 m 可达半径、0.14 m 开口和 72.15 kg 平台质量仅属于 reference_proxy；正式模型必须依据实际资产、安装件和相机假设重新计算总质量、重心、吃水及 IK／夹持可行的目标。只有 Piper 资产时不能改名冒充 Piper H。
4. 核对每项证据所对应的资产、代码、配置、命令与文件是否仍可获得。reference_proxy 的 PASS 不得转记为正式 Piper 或硬件验证；资产、代码或参数变化使旧证据失效时，写明受影响项目并重新验证；没有变化且证据充分的项目不必重复运行。
5. 区分 NOT_RUN、PASS、FAIL、BLOCKED。列出尚未完成的最小问题集合，然后直接开始修复、运行和分析，不要只返回下一步计划。

保持 A→B→C→D 的集成顺序：
A 正式资产审计、装配与静水（相机质量假设已纳入且总质量重算），对应 P1-01/02；
B 按资产限位建立执行器、船臂耦合与腕部相机安装，对应 P1-03/04，并准备 P1-08；
C 规则波、真实接触和腕部成像，对应 P1-05/06/08；
D 步长、检查点恢复与证据汇总，对应 P1-07。

用户授权核验的 π 项目记录为 Piper H、官方夹爪、腕部 Orbbec DaBai DC1，只有腕部相机。采用仓库中的原生契约：RGB 640×480、约 30 Hz；原始深度 640×400、毫米单位、尚未与 RGB 对齐。两路分别保存采集时间、帧号、标定定义与原始分辨率，不能把 resize 或理想对齐诊断当作真实配准。

手眼、真实安装外参、内参／畸变核对及称重惯量未完成。0.15 kg 相机质量与 60° 垂直视场仍标为 virtual_provisional；正式模型据实际资产及所用假设重算质量和静水参照。恢复时同步 RGB／深度各自的采样调度、帧号、标定配置标识和必要观测缓存；P1-08 应验证原生未对齐契约，而非只检查理想 RGB-D。

针对最早未解决的依赖问题推进。可以并行处理独立模块，但明确文件所有权，由一个主集成人统一集成和推送。不要以任意墙钟截止时间中断正常运行；实验按规定的仿真时间或明确失败条件停止。遇到无法解决的外部限制时保存检查点、命令和错误证据，报告具体阻碍，不声称未运行的后台任务会继续。

遵守自由船体、真实动力学连接、真实接触、每物理步更新水动力及正确时间戳的要求。禁止用固定船体、强写位姿、闭爪焊接、重复计重或调宽验收阈值掩盖问题。所有设计调整都说明理由并重新验证受影响的结果。

实际可用 GUI 时检查 viewer；无 GUI 时完成可运行的数值和离屏验证，并分别标注哪些画面没有实际观察。报告中的失败、无法运行、尚未验证必须保留。

完成后更新状态、报告及机器可读指标，按证据协议保存原始数据与可获取的路径。正常提交并推送本任务成果，保留用户改动，不强推、不绕过分支保护；远端变化先整合并复核。最后验证远端提交与文件。

最终输出：
- 从哪个提交和检查点恢复；
- 本轮解决了哪些具体问题；
- 当前正式资产的来源、版本、许可与参数审计，哪些结果仅为 reference_proxy 对照；
- 八项验收的当前状态、指标与证据；
- 原生 RGB／毫米深度契约的成像证据及尚未完成的实物标定；
- 哪些旧结果被重新验证，哪些仍有效；
- 尚存的限制或阻碍；
- 提交 SHA、远端分支和同步验证；
- 是否达到阶段一结束条件。

阶段一未完成时继续完成已授权工作；全部通过后报告结果，不自动进入 P2 或任何学习算法训练。
```

## 续跑时的一个关键区别

“上次没有做完”和“上次已经通过、但代码后来改过”不是同一种情况。前者继续缺失工作；后者先判断哪些证据失效，再进行有针对性的复核。详细状态与有效性规则见[证据协议](../docs/EVIDENCE_PROTOCOL.md)。
