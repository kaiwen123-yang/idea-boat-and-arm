# 证据、状态与可复现规则

## 状态含义

| 状态 | 含义 |
|---|---|
| NOT_RUN | 尚未执行；包括仅完成设计、解析核算或实现的情况 |
| PASS | 对指定代码、配置和适用条件，实际运行满足全部适用判据且证据可访问 |
| FAIL | 已运行，至少一个判据未满足；保留失败及定位 |
| BLOCKED | 所需条件不可用，无法完成检查；写明依赖和已尝试办法 |

每个 P1 项目可以有子配置和子检查，但主项不能只靠一个简化子配置通过。旧 reference_proxy 的通过不替代正式 Piper 场景；改变核心资产、质量、海洋载荷、时间或传感器配置后，重新验证受影响项。

初始化检查只报告 BOOTSTRAP 检查结果，不改变上述物理状态。P1 的实现正确和数值一致不等于模型已通过真实船体辨识。结论写明证据层次和有效范围。

## 每次运行的最少清单

每个运行应有唯一 run_id；建议在 runs/<run_id>/ 保存原始产物，整理可审阅证据到 results/<run_id>/。run_manifest 至少包含：

- case_id、配置档（reference_proxy 或正式具体变体）、种子、完整命令；
- 代码提交；若工作树有改动，同时保存可重现补丁及其校验和；
- 展开后的实际配置与校验和、模型/网格来源提交与校验和；
- Python、MuJoCo/后端、主要依赖与平台版本；
- 仿真步长、控制/传感器周期、求解器、容差和启用的物理项；
- 初态、波浪实现/相位、控制脚本/策略版本；
- 原始轨迹与图像位置、单位和字段说明；
- 指标计算代码、选窗规则、阈值、结果、异常和停止原因；
- 仿真时长、实际运行时长、硬件资源；图像采集时间与墙钟分开。

文件路径应相对仓库或对应可访问的持久外部位置。不能只给临时执行环境的绝对路径。大产物保留内容摘要、大小与校验和，说明获取方式；仓库中的精简图表仍须能追溯到原数据。

## 必须区分的证据

- 配置被成功解析，不等于模型已经运行。
- 波面和船看起来会动，不等于水动力载荷正确。
- 物体被夹爪包围，不等于接触力真实承载。
- 静止采集无丢帧，不等于动态图像/关节时间对齐。
- 理想图像/深度通过，不等于真实水面和冰面视觉有效。
- 预测 RMSE 低，不等于动作导数正确或策略因此更好。
- 视频显示一次成功，不等于统计成功率或泛化结论。
- 一种高保真求解器与另一后端一致，不等于两者都符合真实物理。

## 失败与修订

保留失败运行的配置与结果；可以清理重复大文件，但不能删除使结论不成立的关键反例。每次修复说明原问题、原因、修改及受影响检查。阈值或任务改变必须记录理由，不在观察结果后无说明调整。

只对当前相关风险扩展测试。对接触应分别报告积分量/准静态量和瞬时峰值；不因峰值步长敏感就直接删除它。多步长改变时保持动作和采样的物理时间定义。

## 未来学习实验

训练数据、验证条件和测试海况/物体/目标身份应明确分离。效果优先，允许充分随机干预和大预算；另报告对照中的数据量、运行量、模型容量与资源，不把“使用更多预算”误归因为算法机制优势。

对随机扰动、结构化扰动、主动采样等保留同条件比较；不提前宣布哪类更好。主实验可扩展到效果饱和，同时提供用于归因的预算曲线或受控对照。多种子和置信区间按实际变异决定，不能只报最好的种子。

报告必须包含负结果、失败类型和贡献边界。没有真实证据时，使用“假设/计划/待验证”，不用“已解决/已证明”。报告模板见 [RUN_REPORT](../reports/templates/RUN_REPORT.md)。
