# 阶段一实施规格：建立并验证最小船臂仿真环境

> 状态：**DESIGN ONLY；尚未实现或运行仿真。所有 P1 实验初始为 `NOT_RUN`。**
>
> 本文件定义阶段一的物理范围、接口和交付内容。数值配置的唯一主文件是 [`configs/phase1_design.json`](../configs/phase1_design.json)。本文件中的解析数值来自 `reference_proxy` 通用诊断配置，不是 Piper 硬件参数或实验结果。正式 P1 场景必须绑定来源固定的 Piper 资产并重算参照量。

## 1. 阶段目标

建立一个可观察、可复现、载荷路径明确的 CPU MuJoCo 环境：

- 一艘六自由度自由漂浮的船；
- 安装在船上的 Piper 家族机械臂与对应官方夹爪，具体变体由固定来源的资产和配置明确；
- 随腕部运动的相机和显式具有设计质量的安装结构；
- 一个独立漂浮的刚性目标；
- 共享的确定性波场、浸没相关浮力、阻尼与有限推力的推进器；
- 普通关节控制、简单末端跟踪和确定性动作脚本；
- 能够解释船臂反作用、接触和出水负载转移的数值记录。

阶段一的主演示从目标已经位于可达范围内开始，在静水中完成 **接近、闭爪、保持、缓慢提起、放回、释放**。此前先完成低速推碰，以隔离接触实现问题。同步检查实际渲染的腕部 RGB 与原生深度，确认相机位姿、投影、单位与采集时间语义。

### 已确定的项目约束

- **效果优先。** 不以臆测的仿真预算或效率压力预先裁减必要的动作采样、随机激励和失败分析。采样规模由覆盖与证据需要决定；未来算法比较同时报告资源开销，但不能用节省开销替代效果验证。
- **正式版本必须采用粒子流体。** 后续需要覆盖波浪生成、双向流固耦合及收敛验证、大规模并行和机器人学习。阶段一的等效载荷仅是可检查的初始物理环境，不能成为最终粒子流体目标的替代品。
- **加入腕部相机。** 阶段一实现光学几何、随动、时间戳和实际成像检查，不训练视觉网络。
- **机械臂暂定 Piper 家族。** 既有 Piper H 记录是参考，不代表本项目最终变体已经确定；不能把通用代理参数改名后当作 Piper 规格。

### 本阶段交付边界

| 本阶段完成 | 后续阶段研究 |
|---|---|
| 自由船体、机械臂与目标的动力学连接 | 自主航行接近与联合 MPC/MPPI |
| 简单几何的静水力、阻尼和规则波输入 | 正式粒子流体、波浪生成及双向流固耦合收敛验证 |

| 腕部相机几何、时间语义与原生 RGB/深度成像 | 视觉网络训练与感知误差下的控制 |

人工感知、推理、通信延迟设为零。命令生成和实际施加时刻仍需保存；本阶段不需要提前建设完整异步推理系统。

不得据阶段一结果宣称已验证真实海况、实际湿冰接触、语言泛化、学习算法优势或论文级方法贡献。

## 2. 基准场景与参数来源

场景分成两个层次：`reference_proxy` 用于解析静水力等可隔离诊断；Piper 资产绑定场景用于正式船臂、接触与相机验收。数值参数保留来源类别。硬件参考来自用户授权的既有对话记录，**未独立复核原始实测文件**；不得据此宣称新项目已经完成验机、标定或称重。

### 2.1 坐标与单位

- 世界系为右手系，`z` 向上，静水面为 `z = 0`。
- 船体系 `x` 向前、`y` 向左、`z` 向上；原点位于两个浮筒几何中心的中点。
- 长度用 m，质量用 kg，力用 N，力矩用 N·m，内部角度用 rad。
- 姿态状态采用有效旋转表示；日志注明四元数顺序与方向。
- 力、速度和位置必须声明坐标系及参考点。不得把海洋文献中的 NED 公式直接用于 `z` 向上的场景。

### 2.2 Piper 资产绑定要求

公开资产候选是 [AgileX `agx_arm_urdf`](https://github.com/agilexrobotics/agx_arm_urdf)。实施时固定具体提交，选择明确的 `piper` 或 `piper_h` 基础模型及对应官方夹爪 Xacro，保存展开后的 URDF、导入配置、来源与许可。Piper H 是既有参考，不自动成为本项目最终型号。

正式模型必须核对并导入：关节轴与限位、连杆质量/惯量、官方夹爪的实际运动映射与净开口、工具安装关系、碰撞几何及可获取的额定负载资料。不得为了让演示通过而放大夹爪行程或缩减机械臂质量。

正式平台质量按资产计算，例如 `M = M_boat + M_arm_asset + M_gripper_asset + M_camera_mount`，但若 URDF 已包含夹爪或附件，不能重复计入。若官方模型缺少必要惯量或与所选变体不符，应记录缺口与代理处理；这不阻止先做 `reference_proxy` 水静力，但不能把未对齐资产标为正式 P1 通过。

原目标的 `0.10 m` 抓取方向宽度和 `0.972 kg` 质量并非已验证适合 Piper。正式场景需校核净开口、相机附件与目标的合计负载、可达抓取姿态和碰撞。可调整目标横截面、安装位置或初始位置并记录理由，同步重算目标质量、浮力和接触参照；不能修改真实夹爪行程迁就目标。原 `x ≈ 0.85 m` 初始位置也不强制用于 Piper 场景。

水面几何只用于显示及载荷计算，不能作为承托船和浮体的刚性碰撞平面。夹持目标不启用任务触发的焊接、黏附或直接位姿绑定。

### 2.4 装配时必须确定的量

开发者应以所选 Piper 资产为基础核对连杆和夹爪质量、惯量与重心，随后输出整体审计表。MuJoCo 的光学 camera entity 本身不代表物理载荷；新增质量由腕部子树中的 `camera_mount` 刚体表示，避免漏计或计入两次。`0.15 kg` 是相机与安装体的虚拟假设，真实附件质量和惯量尚未称量；必要的理想化几何也应注明来源类别。驱动力上限应结合可获取的规格与示范轨迹负载确定，缺失的数据不得冒称实测。

初始和主要伸臂构型应检查静态稳定性。若重心偏移引起静态纵倾，允许模型达到相应平衡；不得增加未定义的姿态弹簧来把船强行保持水平。

## 3. 解析参照与适用条件

水平、对称、规则水线面诊断配置的水线面积为：

\[
A_{\mathrm{wp}} = 2(1.40)(0.18)=0.504\ \mathrm{m^2}.
\]

仅对 `reference_proxy`，包含假设腕部相机安装体、总平台质量为 `72.15 kg` 时：

\[
d_0 = \frac{72.15}{1000\times0.504}=0.1431547619\ \mathrm m.
\]

| 参照量 | 设计计算 |
|---|---:|
| 水平平均吃水 | `143.155 mm` |
| 浮筒干舷 | `156.845 mm` |
| 水平船体几何中心世界高度 | `+6.845 mm` |
| 目标体积 | `0.00108 m³` |
| 目标质量 | `0.972 kg` |
| 目标水平吃水 | `54 mm` |
| 目标水平中心世界高度 | `-24 mm` |
| 目标露出水面高度 | `6 mm` |
| 目标重量 | `9.53532 N` |
| 中央添加 `5 kg` 校准载荷的吃水增量 | `9.920635 mm` |
| 升沉恢复刚度 `ρgA_wp` | `4944.24 N/m` |

对称静水诊断可以使用质量等效的中央配重构型，隔离几何与浮力计算。该配置必须与完整 Piper 场景清楚区分。绑定 Piper 后重新计算总质量、排水参照、静态姿态和稳定裕度；不能用本表直接验收。安装真实关节链后的静态倾斜，应按实际排水体积、重心及力矩平衡评价。

无相机的 `72 kg` 配置仅作为代理对照，其水平参考吃水为 `142.857 mm`。含相机的 `72.15 kg` 也仅是代理配置，二者均不得充当正式 Piper 平台质量。

若保留代理目标、水线面积近似不变且排除夹爪自身浸没变化，目标被船完全承载的平均吃水增量约为 `1.928571 mm`。Piper 场景调整目标后须重新计算。真实提起过程存在船姿、夹爪浮力和加速度变化，不能不加修正地把此数值作为全过程硬阈值。

## 4. 水动力模型

### 4.1 分工与唯一载荷来源

MuJoCo 处理重力、刚体多体动力学、关节驱动及固体接触。海洋模块处理浮力、阻尼及外源波场。首版关闭会重复计力的原生密度/黏性流体载荷与 `gravcomp`，并在配置中显式记录。

首版海洋载荷可写为：

\[
\tau_{\mathrm{marine}} = \tau_b(\eta) + \tau_d(\nu-\nu_w) + \tau_{\mathrm{thruster}}.
\]

规则波首先通过波面 `η` 和局部流速 `ν_w` 影响浸没与阻力。另加独立波浪力时必须说明其物理来源，不得同时计算同一压力或恢复作用。

### 4.2 浸没体积与浮心

对参与载荷计算的几何求浸没体积和浮心：

\[
\mathbf F_b=\rho gV_{\mathrm{sub}}\mathbf e_z,\qquad
\boldsymbol\tau_b=(\mathbf r_{\mathrm{CB}}-\mathbf r_{\mathrm{COM}})\times\mathbf F_b.
\]

静水下优先使用规则凸体与水平面的几何裁切；规则波下可采用局部分段或积分近似。若使用离散浮力，需要检查体积、一阶矩、水线面二阶矩及分辨率收敛。

矩形水线面连续二阶矩为 `A_wp B² / 12`，四角等权采样得到 `A_wp B² / 4`。因此仅用四角点浮力可能把相关恢复刚度放大约三倍，不能只凭“船浮起来了”验收。

部分浸没几何必须连续处理。若采用体素近似，应报告分辨率和部分浸没规则，不能用数毫米的体积台阶支撑 `0.1 mm` 的静水吃水验收目标。

目标提起时仍保持独立刚体，其重量由接触传给夹爪和船体，不手工改变船体质量。进入水中的夹爪几何应纳入相应载荷；如采用简化，需在结果中声明并检查其影响。

### 4.3 阻尼与高级水动力边界

采用相对流速下可检查的线性或二次阻尼。初始系数可以根据设计衰减时间或阻尼比设置，但必须注明未辨识，不得称为实船水动力参数。

静水无主动输入时，阻尼功率应有耗散方向。提高阻尼以掩盖错误振荡或抹去船臂反作用，不属于有效修复。

本阶段暂不包含附加质量、辐射记忆、绕射、船尾流、破碎波、显著上浪、冰破裂与融化。尤其不得通过增加刚体质量来替代附加质量，再导致重力和吃水同时改变。后续结论若依赖这些效应，需要单独实现和校验。

### 4.4 确定性规则波

\[
\eta(x,y,t)=A\cos(k_xx+k_yy-\omega t+\phi).
\]

首版为静水和两种单频规则波方向，幅值 `0.01 m`，周期 `2.5 s`。波数、周期和局部流速来自同一套明确声明的波浪假设。若采用深水线性波，应显式记录该假设及色散关系；不把任意独立设置的波长、周期和流速称为一致波场。

波场是位置与仿真时间的确定性函数。显示、额外状态查询或保存检查点不应改变波浪。船与目标查询同一外源场，但各自按当前状态重新计算载荷。不得直接规定它们的正弦位姿，也不得把原轨迹水动力原样回放给改变动作后的分支。

## 5. 驱动、接触与控制

- 机械臂使用普通关节控制或 IK 产生参考，实际运动由有限执行器求解。
- 动作脚本使用仿真时间驱动，接近、闭爪和提起采用低速连续参考。
- 夹爪开口、驱动力与摩擦均记录；不使用无限刚的位置写入替代夹持。
- 推进器控制量首版定义为限幅后的推力。若增加一阶响应，必须记录内部状态且与零人工延迟区分。
- 推进器力在其实际安装位置施加，完整力矩由作用点和质心关系产生。
- 接触力通过官方接口读取，并转换为“作用于目标的世界系合力”；明确接触坐标系和正负号。

## 6. 腕部相机

相机位于实际腕部/工具安装子树。光学相机的相对位姿由选定腕末端和安装几何确定，写入配置并版本化；不能编造已经完成实测手眼标定。

腕部相机硬件参考为既有记录中的 **Orbbec DaBai DC1**：RGB `640 × 480`、约 `30 Hz`，原始毫米深度 `640 × 400`，两路未配准。这些是授权对话记录，未独立复核原始实测文件；新项目需要重新核对最终内参、畸变、外参与流格式。详见 [`CAMERA_SPEC.md`](CAMERA_SPEC.md)。

阶段一必须实际生成并检查 RGB 与原生深度两路输出。这里的原生深度是按 `640 × 400` 独立渲染和导出的未配准仿真数据，用于验收既定数据接口，不代表本项目已采集实物深度。两路分别保留分辨率、内参、坐标系、时间戳和单位；不能用缩放深度图或相同像素索引代替真实配准，也不能将理想仿真深度视为真实水面或冰面上的有效深度测量。这一接口要求不强制未来视觉策略使用深度。

RGB 仿真初始设计为 `640 × 480`、`30 Hz`；原生深度为 `640 × 400`，模拟频率先取 `30 Hz`，实物深度频率尚未核验。两路初期使用理想几何成像，垂直视场角 `60°` 及分别从各自分辨率推导的内参只属于虚拟相机，不能标成 DC1 标定值。允许初始诊断使用同位姿理想光学头，明确标为 `synthetic`；不同原生网格仍然不构成逐像素配准，不能宣称已标定真实 RGB–深度外参或双目基线。真实 `K`、畸变、腕部外参和附件质量均待本项目核对。相机坐标约定、`T_WC`/`T_CW` 的方向及与腕部的关系必须明确。实际图像中应能看到夹爪和目标，并有用于检查投影、深度数值与遮挡的诊断场景。

深度内部以 SI 米处理，按明确规则导出毫米数据；注明深度是光轴距离还是射线距离，以及有效掩码、无效值、量化和裁剪范围。用已知几何距离检查数值、单位及投影，不能只生成颜色好看的深度可视化。保存原始数值深度及其可视化，两者使用相同数据和有效掩码。

由于 `30 Hz` 不整除 `500 Hz` 物理步率，应按仿真时钟安排采集。例如使用绝对目标时刻 `n / fps`，在达到目标时刻的物理步采样，保存目标时刻及真实采集时刻。不能简单固定每 `16` 或 `17` 个物理步拍一帧并宣称精确 `30 Hz`，也不能把渲染完成的墙钟时间冒充采集时刻。

每路图像数据关联各自采集时刻的船体、腕部与目标状态；不从相同设计频率推断实物两路天然同步。渲染前将运动学刷新到采集时刻，避免图像使用旧状态而元数据标记新时间；先保存本物理步的接触结果，避免刷新后覆盖原步记录。每路输出至少包含传感器标识、帧序号、实际仿真采集时间、分辨率、投影参数/内参及来源类别、相机世界位姿、腕部到相机的变换及坐标约定；深度另含单位、定义、有效性与未配准状态。

headless 渲染可以完成成像验收；viewer 可用性不是必须的数值验收条件。若实际渲染环境不可用，应将图像检查记为受阻，不能用投影公式或占位图片宣称成像通过。实际图像应经视觉检查，不能仅检查文件存在。

## 7. 模块与物理步时序

模块分为：场景参数、波场、海洋载荷、控制脚本、MuJoCo 适配、腕部相机、记录显示。相机安装体属于场景动力学，光学成像属于相机模块。

海洋载荷模块输出统一的 `(body_id, point_world, force_world, free_torque_world, category)`，或者关于质心的总载荷。两种表达只能选择一致的施力路径，不能重复计算力臂力矩。波场与载荷模块不控制 viewer、不推进仿真时钟。

初始数值设置：`implicitfast`，物理步长 `0.002 s`，控制参考周期 `0.02 s`，每物理子步重算水动力。步长对照使用 `0.001 s`，控制参考周期保持 `0.02 s`。显示目标约 `30 Hz`，可独立降低，不改变物理逻辑。

推荐单步顺序：

1. 确定 `t` 和本步控制参考。
2. 调用 `mj_step1`，更新当前运动学与速度相关量。
3. 使用当前状态计算浸没、波场和海洋载荷。
4. 清空本项目管理的外力汇总缓冲，汇总后施加一次，设置执行器控制。
5. 记录积分前状态和实际施加输入。
6. 调用 `mj_step2`。
7. 保存本步接触求解结果与积分后主状态。
8. 刷新成像与显示所需运动学，按相机仿真时钟采集并保存元数据，再按独立显示周期更新 viewer。

`mj_step1/mj_step2` 适用于单步积分器；不得配置 RK4 后仍按此路径假定使用了 RK4。物理回调中不得隐式推进脚本阶段、改变随机状态或更新时间。

步进后的部分派生字段仍可能对应积分前状态。记录应区分 `state_before`、`input_applied`、`contact_result_during_step` 和 `state_after`；生成后续世界模型数据时，保证 `(s_t, u_t, s_{t+Δt})` 一致。

自定义外力不自动获得原生隐式流体项的全部导数处理，`implicitfast` 不替代时间步检查。

## 8. 保存、恢复与未来分支接口

使用适当的 MuJoCo 状态接口保存积分所需状态，包含执行器、时间、用户输入及 warmstart。首版关闭非必要的 sleeping；启用 sleeping 后不能再假定紧凑状态覆盖整个求解状态。

还需保存引擎外的：

- 波浪参数、相位与外源随机状态（若使用）；
- 控制脚本的阶段和内部变量；
- 推进器内部状态；
- 命令和执行记录所需状态；
- RGB 与深度各自的下一目标采集时刻、帧序号及相关调度状态；
- 配置、模型版本及状态布局标识。

阶段一仅检查同状态、同输入的短时复现；不实现主动采样、方向导数监督或梯度可靠性网络。
