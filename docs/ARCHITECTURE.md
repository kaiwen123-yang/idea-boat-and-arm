# 系统接口与实现分工

这是待实现架构，不是现有可导入的 Python API。初期建议 src/boat_arm/，以 CPU MuJoCo 为后端；不要为未来后端先搭建复杂框架。各模块只保留真正需要的边界。

## 模块

| 模块 | 负责 | 核心输入/输出 |
|---|---|---|
| 场景与配置 | 资产、质量惯量、关节树、接触、配置解析 | 配置与资产清单 → 版本化模型、对象索引 |
| 波场 | 确定性的波面与局部水速度 | 位置、仿真时刻、实现标识 → η、流速 |
| 海洋载荷 | 浸没几何、浮力、阻尼、诊断量 | 当前位姿/速度、波场 → 点力和自由力矩 |
| 驱动与动作脚本 | 关节参考、有限驱动、推进器限幅 | 时间、状态、脚本阶段 → 实际输入 |
| MuJoCo 适配 | 正确施力、步进、接触、保存恢复 | 模型与输入 → 下一状态、接触结果 |
| 腕部相机 | 投影、采样、RGB/原生深度、元数据 | 新鲜运动学、采样调度 → FramePacket |
| 证据记录与显示 | 轨迹、图像、指标、viewer | 有时刻标签的数据 → 可复现运行产物 |

相机安装体的质量属于场景模块，光学成像属于相机模块。显示与日志不能暗中推进物理时钟、改变波浪相位或消耗物理随机数。

## 统一约定

内部采用 SI，世界 z 向上，船体 x 前、y 左、z 上。T_AB 表示 B → A。四元数使用 wxyz 并记录左/右乘含义。每个速度和载荷明确所用坐标系、参考点以及作用对象。

海洋模块可返回：

~~~text
MarineLoad {
  body_id,
  point_world_m,
  force_world_N,
  free_torque_world_Nm,
  category,
  evaluation_sim_time
}
~~~

使用力作用点时由适配层计算力臂；若直接提供质心总力矩，就不要再添加同一力臂。重力和机械臂关节反作用由物理引擎负责。每个子步重新汇总由项目管理的外载荷，防止上一步残留或重复累加。

## 一步的时间语义

每次环境初始化，在 t=0 刷新运动学并采集第 0 帧，然后将下一目标帧时刻设为 1/fps。恢复检查点时使用已保存的调度，不重复生成初始化帧。此后的单步顺序为：

1. 取当前仿真时刻 t，确定此物理区间适用的控制参考。
2. mj_step1 更新该时刻的运动学/速度相关量。
3. 查询共享波场，按当前浸没状态重算海洋载荷；清空管理的外力缓冲并施加。
4. 保存 state_before 和 input_applied，调用 mj_step2。
5. 保存此次接触求解结果以及积分后的主状态。
6. 为相机/下一步诊断刷新所需运动学，采样和记录带准确时间标签的图像与状态。

mj_step1/2 路径按官方接口用于单步积分器；不把设置 RK4 后落到其他积分路径的结果标为 RK4。控制/物理回调不能通过被调用次数推进脚本；某些刷新函数可能重复求值。

主状态更新与派生量刷新分开。不要把 mj_step2 后未更新的 xpos、xmat 等直接标为新时刻。若刷新会改变接触缓存，先复制需要保存的求解结果。训练数据必须对应同一状态转移，而非错位拼接。

接口依据：[MuJoCo simulation](https://mujoco.readthedocs.io/en/stable/programming/simulation.html)、[API](https://mujoco.readthedocs.io/en/stable/APIreference/APIfunctions.html)。实际安装版本须固定。

## P1 动作与后续延迟

P1 初期使用关节参考、夹爪参考与左右推进器推力，保持动作单位和限幅透明。实际施加值与生成参考分别记录，不能只保存“期望动作”。

后续 P2 扩展动作记录：

~~~text
ActionRecord {
  generation_time, intended_apply_time, actual_apply_time,
  duration, command, applied_command, source_policy_version,
  committed_prefix_id, goal_version
}
~~~

已进入不可撤回执行段的动作不能在预测或分支中被改写。一个训练步跨越队列切换时，需要完整实际动作序列，不应只取末端命令。P1 只留字段与清晰时序，不提前实现完整异步系统。

## 检查点与分支

引擎状态使用所需的完整积分状态接口，不能只存 qpos/qvel。保存模型/配置指纹、时钟、驱动、输入与 warmstart；引擎外保存波浪实现、RNG、脚本阶段、动作队列、传感器调度和帧号。P1 关闭非必要 sleeping；若以后启用，需重新确认完整状态范围。

未来在同一检查点比较动作分支时，固定初态、外源波浪实现和已经提交的动作前缀。然后按各分支的真实新状态重算浸没和水动力。固定外扰不等于固定回放外力；两者物理含义不同。

## 真值、观测与目标一致性

SimulatorState 包含诊断所需真值；ObservationPacket 只包含策略可取得的传感器和时间信息。训练特权教师或 critic 时单独记录可见字段，正式闭环比较使用一致观测权限。

后续语言任务记录不可被静默重置的 goal_version、用户目标描述和约束。感知模块维护 target_belief、身份置信度与重识别历史；不能把模拟器目标整数 ID 当作已解决的视觉身份识别。恢复策略可以改变动作阶段，但应保留任务目标并报告是否误操作其他物体。

动作条件世界模型的输入至少应明确：观测历史/信念、实际动作历史、候选未来动作、已提交前缀、未来时间间隔。输出预测与不确定性如何用于策略训练或在线规划，应由 P3/P4 实验分别确定，不能以模块拼接声称机制有效。
