# 研究与实施路线

整理日期：2026-11-18。

当前状态见 [reports/STATUS.md](../reports/STATUS.md)。本次仓库初始化只建立规划、参数与执行规则；**P1 仿真尚未实施，P1–P7 与粒子流体 F 支线的实验均未完成**。自动任务以当前状态和用户本轮授权为准，不能因为路线图存在就提前开展后续训练。

用户在 2026-11-18 明确：以效果为主，允许充分随机探索；最终版本采用粒子流体，同时解决波浪、双向耦合、并行与学习；机械臂暂定 Piper 家族，并加入单腕部相机。用户同日允许只读使用 π 系列算法与腿臂协同控制项目的相关硬件事实，科学论证仍不依赖无关记忆。以下路线已纳入这些约束。

## 1. 推进顺序

| 阶段 | 主要问题 | 主要交付 | 进入下一阶段的依据 |
|---|---|---|---|
| **P1 最小物理环境与腕部相机** | Piper 资产与装配参数是否对齐，模型是否实现正确、数值可复现，腕部成像和时间/坐标是否一致？ | 已固定的硬件资产、CPU MuJoCo 场景、规则水动力、8 组检查、接触演示、腕部图像与记录 | 资产与质量/限位审计、基础物理关系、相机接口与数值检查通过，已知简化明确 |
| **P2 强控制基线与延迟** | 有物理先验和扰动估计的控制器能做到什么？ | 联合控制基线、连续物理时钟、观测/执行队列、可复现延迟工况 | 基线能力和失败边界明确，延迟确实作用于闭环 |
| **P3 世界模型与梯度诊断** | 学习模型的预测和梯度是否有助于控制？ | 联合状态模型、SuperMimic 式训练迁移、采样对照与方向诊断 | 模型误差与策略改进之间的关系有物理环境证据 |
| **P4 发展方法** | 隐藏外扰、执行前缀和接触切换下如何获得有效动作响应？ | 充分随机干预对照，以及与 DDPPO 等近邻对比的归因或可靠性机制 | 充分效果验证与受控归因试验支持机制解决了明确失败 |
| **P5 视觉语言完整任务** | 方法能否支持正确目标、接触转移与失败恢复？ | 真实观测接口、多目标语义、遮挡与恢复闭环 | 完整任务收益可复现，未使用部署不可得信息 |
| **P6 粒子流体与算法合流** | 完整策略在经过校验的粒子流体中是否有效？ | F 支线与船臂模型、观测、执行时序和学习框架整合 | 波浪、双向耦合、数值收敛、并行与任务效果都有证据 |
| **P7 独立物理证据与论文** | 方法主张能够覆盖多大物理与任务范围？ | 辨识/水槽/独立模型证据、跨条件实验、可复现发布和稿件 | 每项结论与实际证据一致，投稿定位据此决定 |

P1 优先 CPU MuJoCo。物理定义验证后再评估 MuJoCo Warp 的批量训练需求。P1 通过后，P2 控制主线与 [F 粒子流体支线](FINAL_FLUID_TRACK.md) 可以并行推进。F 支线选择适合的粒子求解器和双向刚体耦合方式，最终在 P6 合流；粒子流体是正式目标，不是可选的展示效果。

当前框架包括 Isaac Lab 在内的实际选型，应依据所需耦合、成像、并行和学习能力决定，不把框架名称当作物理正确性证据。

## 2. P1：建立并验证最小物理环境

范围由 [PHASE1_SPEC.md](PHASE1_SPEC.md) 和 [phase1_design.json](../configs/phase1_design.json) 定义，执行任务见 [PHASE1_TASKS.md](PHASE1_TASKS.md)。

顺序为：

1. 固定 Piper 具体型号、资产版本与夹爪，审计质量/惯量、关节与执行器限位、安装变换；记录官方资产值、实测值和设计假设的来源。Piper H 是当前参考配置，尚不等于最终型号已确定。
2. 场景装配、整机质量/惯量核对、静水浮力与恢复。
3. 机械臂驱动和船体反作用、推进器作用。
4. 共享规则波场、推碰、夹持、缓慢提起与释放。
5. 单腕部相机挂载、成像、遮挡/视场检查和时间/坐标核对。
6. 步长对照、完整检查点恢复、证据汇总。

旧通用机械臂与平台参数保留为 `reference_proxy`，不能冒充 Piper 规格或代替正式资产对齐。硬件检索属于“授权对话检索记录，未独立复核原始采集文件”；相机标定与实物称重/惯量仍需完成。配置和边界见 [RESEARCH_SCOPE.md](RESEARCH_SCOPE.md) 与 [CAMERA_SPEC.md](CAMERA_SPEC.md)。

允许普通关节 PD、末端 IK、真值状态和预先可达目标。推进器作用明确，但不要求自主航行。腕部相机在 P1 完成接口和验证，视觉策略训练留到 P5。所有载荷、接触、图像和物理时间语义必须可追溯。

完成标准以 [PHASE1_ACCEPTANCE.md](PHASE1_ACCEPTANCE.md) 为准，不以程序运行时长或单段成功视频代替。初始工程阈值不能伪装成行业标准；修改参数、模型或阈值需记录原因和影响，不得为掩盖失败而修改。

## 3. P2：强控制基线与真实闭环延迟

### 主要工作

- 建立部署可用观测条件下的状态与扰动估计接口。
- 实现至少一个有物理先验、执行限幅和延迟处理的联合控制基线，例如 MPC 或 MPPI；普通反馈控制作为较简单参照。
- 将接近、相对跟踪和接触过程连接起来，先使用明确目标状态。
- 区分采集、到达、推理完成、入队和实际作用时刻。
- 物理按仿真时钟持续演化，观测与动作按调度到达；不能暂停物理来“等待推理”。
- 固定延迟和抖动由配置控制；未来实际硬件测得的延迟分布可以按相同接口回放。

### 要获得的结果

记录基线在浪况、相对速度、控制权限与延迟变化下的能力。可同时研究有效延迟与接触窗口长度的比值，但接触窗口定义必须明确，不能用算法自己的预测直接充当地面真值。

若基线失败，先分析观测、动作权限、任务几何和物理模型。若基线已完成全部任务，应选择有科学意义且物理可信的进一步问题，而非刻意调坏基线。

## 4. P3：世界模型和策略梯度诊断

### 主要工作

- 采集包含成功、接触失败、滑脱和重新接近的数据。
- 建立船、臂、目标及执行状态的联合模型，优先结构化状态表示。
- 从观测历史和实际执行记录估计未知共同外扰；真值上下文仅用于监督、诊断或上界。
- 借鉴 SuperMimic 的短时可微展开优化策略，物理仿真器继续提供不可微交互数据。
- 预测先覆盖已提交动作前缀，再评价新动作影响；展开长度用物理时间定义。

### 最小比较

| 比较 | 目的 |
|---|---|
| P2 的强物理基线 | 检验学习方案是否有实际增益 |
| 直接物理仿真采样训练 | 检验世界模型是否必要 |
| 在同一世界模型中采样更新策略 | 分离廉价模型轨迹与解析梯度的收益 |
| 通过学习模型反向传播的策略训练 | 诊断模型梯度的实际作用 |

状态预测误差、候选排序、局部动作方向改善和完整闭环策略更新效果分别报告。低状态误差不代表梯度有效；局部方向改善也不代表完整策略更新一定有效。训练允许充分随机探索；计算与数据开销如实记录，受控预算对照用于科学归因，不能成为提前限制最终效果的默认理由。

若没有发现可靠增益，不直接扩大模型或提前接入 VLA。先确认数据分布、时间对齐、外扰可观测性、接触切换和模型使用方式。

## 5. P4：发展明确的新机制

候选方向是固定物理检查点、外源驱动和不可撤销动作前缀，仅改变新动作，研究有限时域后果及模型方向可靠性。它不是预先认定的最终算法。完全随机动作干预是正式实验路径，允许充分运行；是否采用主动选择由实际效果决定，不以预设的采样效率论断替代实验。

需要比较的近邻与控制组包括：

- 普通预测损失与相同策略优化器；
- DDPPO 式经验近邻方向监督；
- 固定检查点的随机动作配对干预；
- 针对延迟后可控方向、接触阶段或策略需求设计的干预；
- 加入独立方向校验的更新选择；
- 直接采样更新。

MB-MIX 的 Jacobian 监督、展开长度混合以及一阶/零阶估计已有研究，必须准确归属。把解析导数换成有限差分、固定随机种子或加入队列，均不自动形成新贡献。

分支样本计入成本，同时报告充分探索后的最终效果与受控数据量/算力的机制对照。模型在训练分支中表现良好后，仍需在未见过的物理检查点、外扰实现和任务条件中验证。可尝试理论分析，但假设必须适用于实际方法；接触切换处不能套用全局光滑假设。

## 6. P5：视觉语言目标与恢复

### 任务链路

指令解释 → 目标身份维护 → 接近 → 相对跟踪 → 接触 → 转移与释放 → 区域保持验证 → 必要时恢复。

### 主要工作

- 基于 P1 已建立的单腕部相机接口，将状态真值替换为带时间戳和误差的观测估计，并单独报告真值上界；显式评估机械臂/夹爪遮挡、目标离开视野和重识别，不能假定腕部图像始终提供完整状态。
- 使用观测采集时刻的船体/相机姿态转换目标位置。
- 对“指定同一物体”和“每次重新选择目标”明确不同任务语义。
- 高层输出携带任务版本与时间信息，迟到输出不能覆盖已经变化的任务状态。
- 将未抓住、滑脱和身份不确定区分为不同恢复事件。
- 区分高层推理延迟与底层感知、执行延迟，并分别测量架构和预测补偿的收益。

仅将语言解析为固定目标时，称为语言条件控制；要宣称 VLA 能力，需要明确视觉语言到动作/技能输出的训练与泛化证据。恢复必须发生在同一任务中。

## 7. F 支线与 P6：正式粒子流体和算法合流

F 支线在 P1 通过后即可独立推进，详细任务见 [FINAL_FLUID_TRACK.md](FINAL_FLUID_TRACK.md)。建议按以下依赖顺序建设：

1. 选择粒子求解器与刚体后端，核实双向作用，定义状态、载荷与时间接口。
2. 建立指定波浪输入与边界，分别校验水体、浮体和船体响应。
3. 验证双向流固耦合、时间步、粒子分辨率和耦合迭代的收敛。
4. 扩展独立环境并行，确保重置、随机过程和接触数据互不污染。
5. 接入机器人控制、数据采集和学习，依据实际效果发展完整训练。

P2–P5 可以在已验证的等效载荷环境中建立基线和方法，F 支线同时发展最终物理平台。P6 合流时需要明确：哪些算法、参数、数据或模型重新训练，哪些直接迁移，哪些失效及其原因。

粒子流体产生的压力/冲量已经承担某项浮力、阻力或恢复作用时，不得继续叠加同来源的等效载荷。双向反馈、收敛、真实波浪与并行学习都需要独立证据，不能凭粒子渲染或软件名称宣布完成。

## 8. P7：物理证据、复现与论文收敛

根据最终主张补充证据：

- 真实参数、自由衰减、波浪响应或接触数据辨识；
- 自由漂浮船体、机械臂与浮体的水槽实验；
- 与独立可信水动力模型或不同实际物理后端比较；
- 未见过的浪况、延迟、目标形状、接触参数及系统配置；
- 代码、配置、失败分类、原始数值和可核查的结果汇总。

运动平台可以验证底座扰动与延迟下的操作，但不能充分替代自由漂浮船体的双向反作用。使用替代浮体时，结论应对应浮动物体操作；湿冰摩擦、破裂和实际冰区清理需要相应证据。

T-RO 目标由方法重要性、机制解释和证据强度共同支持。更广泛的期刊目标需要更普遍的认识或系统能力，不通过添加更多模块自动获得。
