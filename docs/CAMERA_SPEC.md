## 2. Piper 资产先于正式物理数值

[官方 agx_arm_urdf](https://github.com/agilexrobotics/agx_arm_urdf) 分别提供 Piper 与 Piper H 的模型及夹爪组合入口。初始化时只核对了 README 的型号、目录与用法；尚未固定提交、审核具体惯量、转换或运行这些资产。

Codex 应在 P1 任务 A 中完成：

1. 从官方来源选定具体变体，固定 commit、文件路径和许可。可先核验与既有参考一致的 Piper H 候选；记录其作为仿真起点的依据，不宣称新项目实物型号已最终确认。
2. 导入并审计每个连杆的质量、惯量、重心、关节轴和限位、夹爪行程及执行器限制。固定关节合并不能丢失惯量；原资产的 world 固定连接应正确替换为船体安装关系。
3. 明确官方资产标称参数与真实机器人测量参数的层次。资产有值不代表实物已辨识；不完整或可疑数据应说明来源和影响。
4. 根据相机和安装体的暂定质量重算整体质量、重心、吃水及伸臂稳定性。
5. 检查目标是否能进入夹爪、附件与目标组合负载是否可行，以及船体干涉、IK 与关节余量。可调整目标尺寸、姿态和安装设计；不能任意扩大 Piper 夹爪行程。
6. 将结果写入资产清单和 formal_scene 配置，保留旧 reference_proxy 作为解析诊断。

旧 12 kg 臂重、0.75 m 臂展、0.14 m 开口和 72.15 kg 总质量均为通用代理值。旧目标 0.18×0.10×0.06 m 也不能在未检查夹爪与载荷前默认为正式可抓目标。

## 3. 虚拟相机与真实相机分开

| 字段 | P1 可执行的仿真设定 | 实物对齐要求 |
|---|---|---|
| 光学输出 | RGB 640×480；原生深度 640×400，分别保存 | 核对实际启用流和模式 |
| 采样 | RGB 30 Hz；深度先取 30 Hz 的设计值 | 深度实际频率独立测量，不从 RGB 推断 |
| 视场/内参 | 初期可用垂直 FOV 60° 的理想针孔模型 | 60° 不是 DC1 已核实规格；导入实际 K/D 后替换 |
| 畸变 | 初期理想零畸变 | 记录实际畸变模型、参数与是否整流 |
| 末端挂载 | 明确版本化的名义工具到相机变换 | 真实手眼标定需独立核验 |
| RGB–深度关系 | 分别定义 K、尺寸与名义外参；原生数据不标为已对齐 | 实际配准需真实内外参、单位和有效深度 |
| 附件质量 | 0.15 kg 的设计假设，显式计入腕部子树一次 | 称重、质心与惯量确认后替换 |
| 深度有效性 | 理想几何深度，用于接口和遮挡检查 | 水/冰条件下的无效值、噪声与反射影响需实测或有依据建模 |

允许使用同位姿理想光学头作为初始诊断，但必须标为 synthetic。即使光心暂时重合，不同原生网格也不等于 RGB 深度逐像素配准。真实双目基线未知时不能自行填一个数后标称 DC1 标定值。

垂直 FOV 已知时，理想针孔模型满足 fy = H / (2 tan(FOVy/2))。若假定方形像素，则 fx = fy；cx、cy 按实际像素中心约定记录。不能把水平与垂直 FOV 混用，也不能只改变图像分辨率而沿用不匹配的 K。

光学 camera entity 本身没有机械质量；相机/支架由工具子树中的刚体表示。若已被所选资产包含，则只补未计入部分，不能重复添加 0.15 kg。支架固定在腕部或夹爪固定外壳，不绑定活动夹指。

## 4. 每帧数据契约

每路传感器至少输出：

- sensor_id、frame_id、帧序号、图像尺寸、通道、数据类型；
- 目标采集时刻、实际仿真采集时刻、交付/可用时刻及各自时钟域；
- K、D、投影/畸变模型、是否整流、是否对齐；
- 深度单位、深度是光轴距离还是射线距离、有效掩码与裁剪范围；
- T_WC 及 T_tool_C 的变换方向、相机坐标约定；
- 与采集时刻一致的模拟诊断状态索引；未来策略不自动获得这些真值。

约定 T_AB 将 B 系中的点变换到 A 系。机器人光学系可采用 x 向右、y 向下、z 向前；MuJoCo 相机朝向与光学系需要显式转换。由标志点投影实验核对符号和矩阵方向，不靠名称猜测。

深度导出为毫米整数前，应明确无效值、量化和范围；内部 SI 米与原始毫米不能混用。若后续生成 aligned_depth，单独命名，保存配准变换及有效掩码，保留原生深度。

## 5. 时间与成像验收

500 Hz 物理步率与 30 Hz 采集不能用固定 16 步或 17 步周期准确表示。初始化时先刷新 t=0 的运动学并采集第 0 帧，之后以 n/fps（n≥1）作为绝对目标采集时刻，在首个不早于该时刻的物理步采样；允许实际帧间隔在步长网格上交替，保存时间偏差。改变物理步长后按秒重建调度，不能使相机或动作脚本随步数改变速度。配置中每路的 simulation_rate_hz 是模拟频率唯一来源；reported/measured 字段仅记录硬件证据。

P1-08 检查随腕部移动的外参、夹爪与目标可见性、已知点投影、不同尺寸原生 RGB/深度、无效深度表示、采样与恢复后的帧序号。至少查看实际 RGB、深度可视化和短序列，不能只测试数组尺寸或生成占位图。

本阶段未引入人工推理延迟，但要保留 capture_time 与 available_time 区别。后续 P2/P5 的延迟应作用于真实数据流，而不是仅给策略一个“延迟数值”。

## 6. 单腕部观测对研究问题的影响

单腕部视野跟随控制动作。伸臂、船体摇动和闭爪可能改变目标可见性；接触前后要评估目标离开视野、遮挡和再次识别。这个配置要求后续方法明确处理：

- 观测历史和目标信念，而非依赖每帧都完整可见；
- 相机运动、船体运动和目标相对运动之间的歧义；
- 语言目标描述与物理对象重识别的一致性；
- 必要时主动观察、等待或恢复的决策；
- 可部署观测策略与特权状态诊断的分离。

世界模型可以为这些问题提供预测与记忆机制，但单靠模型名称不能保证可观测性或身份正确。应设计遮挡、出视野、相似浮体、延迟和重现条件测试。外部相机目前不纳入系统前提；不能通过新增未授权传感器静默降低任务难度。

P1 必须验收原生仿真深度接口；P5 的视觉策略可以只使用 RGB。真实水面和冰面深度质量仍待验证。深度不自动替代 VLA 所需的图像输入；若采用已有多相机 π 模型，要明确单腕输入适配、重新训练/微调和比较方案，不能把缺少的第二路 RGB 用深度填入而假定模型等价。
